-- CLEAN LAYERED ARCHITECTURE

-- SEPERATION OF CONCERNS:
Each level in your program should be seperate by a clear barrier, the transport layer, the service layer, the storage layer...

-- DEPENDENCY INVERSION PRINCIPLE (DIP):
You are injecting the dependencies in your layers. You dont directly call them. It promotes loose coupling and makes it easier to test the programs.

-- ADAPTABILITY TO CHANGE:
By organising the code in a modular and flexible way, you can more easily introduce new features, refactor existing code and respond to evolving business requirements.

-- REQUIREMENTS
1. Router: https://github.com/go-chi/chi/v5 (get)
2. Hot reloading: https://github.com/air-verse/air@latest (install)
   -> Run the command "air init"
   -> Make sure to edit the required fields in .air.toml file
   -> Our run command becomes "air"
3. env: https://github.com/joho/godotenv (get)
4. Postgres driver: https://github.com/lib/pq (get)
5. To compose docker.yml file: docker compose up --build
   - To make it work without any error:
     1. Run the command "sudo systemctl status postgresql" and check the status is active/inactive
     2. If active, run the command "sudo systemctl stop postgresql"
     3. Inorder to make it remain inactive even after boot, run the command "sudo systemctl disable postgresql"
6. SQL migrations: https://github.com/golang-migrate/migrate (install)
7. To create migrations:
   migrate create -seq -ext sql -dir ./cmd/migrate/migrations create_users

   -seq: sequential
   -ext: extension
   -dir: destination directory to generate
8. To run up migrations:
   migrate -path=./cmd/migrate/migrations -database="DB_URL in .env" up
9. To run down migrations:
   migrate -path=./cmd/migrate/migrations -database="DB_URL in .env" down
10. Validator: https://github.com/go-playground/validator/v10 (get)
11. To test the concurrency of users updating a post: go run scripts/test_concurrency.go
12. Since we dont care about the existing data, firstly to remove the existing data before seeding, run: TRUNCATE TABLE comments, posts, users RESTART IDENTITY CASCADE;
13. To create the seed for the database: go run cmd/migrate/seed/main.go
14. Swagger documentation: https://github.com/swaggo/swag/cmd/swag@latest (install)
    -> Run the command "swag init -g cmd/api/main.go"
    -> Even the command can be "swag init -g ./api/main.go -d cmd,internal && swag fmt"
    -> Then add this command in pre_cmd of .air.toml
15. HTTP swagger: https://github.com/swaggo/http-swagger (get)
16. Swagger url: http://localhost:8080/v1/swagger/index.html
17. Standard logging: https://go.uber.org/zap (get)
18. Hashing: golang.org/x/crypto/bcrypt (get)
19. Token generation: https://github.com/google/uuid (get)
20. Mailer: https://github.com/sendgrid/sendgrid-go (get)
21. For SendGrid API key and Sender Verification:
    -> Go to: https://app.sendgrid.com/login and create an account
    -> Then go to: https://app.sendgrid.com/settings/api_keys and create an API key and set it in your .env file
    -> Last go to: https://app.sendgrid.com/settings/sender_auth and select "Single Sender Verification" and verify your from email and set it in your .env file
22. CORS: https://github.com/go-chi/cors (get)
23. JWT token generation: https://github.com/golang-jwt/jwt (get)
24. Redis Caching server: docker run -d --rm --name puw-redis -p 6379:6379 redis:6.2-alpine redis-server --loglevel warning
    -> Run the command "sudo systemctl status redis" to get the status
    -> If the status is active, run the command "sudo systemctl stop redis" before running the docker command
25. To check the services run by docker: docker ps --format "table {{.ID}}\t{{.Names}}\t{{.Ports}}"
26. If we want to get the CLI (recommended), refer the docker-compose.yml redis configuration instead of following the above command.
    -> We will have redis-cli and redis-commander
    -> Since postgresql is running through docker, better to make redis also run through docker.
27. Redis Client for Go: https://github.com/go-redis/redis/v8 (get) (redis-6)
28. To get the keys of redis server: docker exec -it [Redis ID] redis-cli KEYS "*" (Get Redis ID by running 25)
29. To get the value of particular redis key: docker exec -it [Redis ID] redis-cli GET [Redis Key]
30. To check the performance: npx autocannon http://localhost:[PORT_ADDR]/users/{LoggedID} --connections 10 --duration 5 -H "Authorization: Bearer [AuthToken]"
    -> Check this with REDIS_ENABLED with true and false to see the optimization difference.
31. For testing: go test -v ./cmd/api
32. For mock testing: https://github.com/stretchr/testify (get)
33. To get the PID of server: lsof -i :[PORT]
